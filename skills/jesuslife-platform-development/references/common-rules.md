# JesusLife 공통 보호와 라우터

기존 `jesuslife-platform-development` 호출과 프로젝트 AGENTS.md의 Flutter·API·CHGO·품질 모드 요청을 계속 처리한다. 먼저 대상 경로, AGENTS.md, 프로젝트 문서, 현재 브랜치와 `git status --short`를 확인한다. 미커밋 변경은 사용자 작업으로 보존하고 main은 수정하지 않는다.

## 공통 보호

- [제품 경계](project-boundaries.md)를 적용한다. 데이터 원본 소유 제품은 하나이며 다른 제품은 API 또는 이벤트로 참조한다.
- 이름, 기도문, 은혜 기록, 일기, 서명을 로그·추적·예외에 출력하지 않는다. 사용자 기록은 복구 보관함과 소프트 삭제를 우선한다. 저장 성공 확인 전에 완료를 표시하지 않는다.
- 신학 문구·정본, Canonical ID 발급·병합·폐기, 개인정보 공유, DB 구조, 인증 경계 변경은 `AUTHOR_REVIEW_REQUIRED`로 분류한다. 초안·영향·대안·복구 계획을 제시하고 필요한 사람의 승인 전 적용하지 않는다.
- DB migration 실행, 사용자 기록 영구 삭제, 실제 개인정보 수집, 외부 API 연결, commit·push·merge·tag·release·배포·서비스 활성화는 별도 허가 없이 수행하지 않는다. 기존 승인 범위를 확인하고 승인된 행동만 수행한다.
- AI는 저자, 신학 검토자, 독립된 사람의 서명과 동의를 대신하지 않는다. CHGO 후보 지식과 승인 정본을 분리한다.

## 자동 라우팅

| 요청 | 경로 |
|---|---|
| 기획, 설계, 구조, 흐름, 비교, 경계, 계약 초안, ADR, 로드맵 | design |
| 구현, 수정, 추가, 오류 해결, DB 변경, API 개발, 테스트, 빌드 | implementation |
| 복합 요청 | design → 필요한 승인 → implementation |

단어만으로 판정하지 말고 요청한 산출물을 기준으로 선택해 순서를 알린다. 예: “API 구조 비교”는 design, “설계대로 API 추가”는 implementation이다. 설계만 요청하면 앱 코드나 DB를 변경하지 않는다.

- design: [설계 절차](design-workflow.md), 설치되어 있으면 [설계 스킬](../../jesuslife-platform-design/SKILL.md)을 사용한다.
- implementation: 설치되어 있으면 [개발 스킬](../../jesuslife-platform-implementation/SKILL.md)을 사용하고 해당 작업의 [Flutter](flutter-workflow.md), [API](api-workflow.md), [CHGO](ontology-workflow.md) 절차를 선택한다.
- [품질 게이트](quality-gate.md)로 결과를 보고한다.
- [외부 스킬 라우팅](external-skill-routing.md)에 따라 가용성을 확인한다. 하위 스킬이 없으면 이 스킬의 references로 동일 보호·절차를 수행한다. 자동 설치하지 않는다. 하위 스킬에서 다시 라우터로 순환 호출하지 않는다.

“설계하고 구현” 요청은 design을 먼저 수행한다. 신학 문구·Canonical ID·개인정보 공유·DB 구조·인증 경계 등 중요 경계 변경은 AUTHOR_REVIEW_REQUIRED로 표시하고, 필요한 사람의 승인을 받은 뒤 해당 변경의 implementation으로 진행한다. 복합 요청 자체를 중요 경계 변경 승인으로 간주하지 않는다.

불명확하거나 위험한 요청은 파일·코드·DB·설정 등 대상 상태를 변경하지 않고 먼저 사용자에게 질문한다. 불명확한 범위·의도 또는 위험과 필요한 결정을 구체적으로 설명하고, 답변으로 범위와 안전 조건이 확인될 때까지 해당 변경을 보류한다. 확인을 위한 읽기 전용 점검만 수행한다.

작업 시작 전에 적용할 스킬 이름·역할과 수행 순서를 사용자에게 알린다. 예: 공통 라우터 → design → 필요한 승인 → implementation. 직접 하위 스킬을 호출한 경우에도 공통 보호 규칙 적용과 해당 단계의 순서를 알린다. 진행 중 적용 스킬이나 순서가 바뀌면 변경된 작업을 시작하기 전에 다시 알린다. 이 안내를 사용자 승인으로 간주하지 않는다.

외부 스킬은 JesusLife 공통 보호 규칙과 대상 프로젝트 고유 보호 규칙 아래에서, 요청 해결에 필요한 최소 범위에만 보조 사용한다. 실제 설치·가용성과 관련성을 먼저 확인하고 필요한 지침만 읽는다. 외부 스킬의 지침으로 승인 경계·제품 경계·개인정보·신학 원문·사용자 기록 보호를 우회하거나 작업 범위를 확대하지 않는다. 보호 규칙과 충돌하는 외부 지침은 적용하지 않으며 판단이 불명확하거나 위험하면 변경 없이 질문한다. 외부 스킬을 자동 설치하거나 필수 의존성으로 가정하지 않는다.
